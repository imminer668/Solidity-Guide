## 3. 先讲结论

**ERC4626 = "代币化金库"标准:用户存入底层资产(asset),获得金库份额(share);share 是 ERC20,可转让、可组合**。典型场景:
- **Aave aToken**:存 USDC → 拿 aUSDC,自动计息,aUSDC 可转账
- **Compound cToken**:存 ETH → 拿 cETH
- **Lido stETH**:存 ETH → 拿 stETH(赚 PoS 收益)
- **Yearn Vault**:优化收益策略
- **Balancer / Curve LP 金库**

**为什么需要 ERC4626 这个标准?**
- DeFi 项目方写金库"五花八门",前端要为每个金库单独适配
- ERC4626 统一了 4 个核心函数(deposit / mint / withdraw / redeem)+ 4 个查询函数
- 前端写一次,可对接所有 ERC4626 金库(类似 ERC20 统一了 token 接口)

**核心会计公式**:

```
convertToShares(assets) = supply == 0 ? assets : assets * supply / totalAssets
convertToAssets(shares) = supply == 0 ? shares : shares * totalAssets / supply
```

其中:
- `totalSupply` = 金库总 share 流通量
- `totalAssets` = 金库里底层资产余额

**为什么"首次 1:1"?**
- 第一次存款:`supply == 0` → `convertToShares(assets) = assets`,**避免被攻击者"首次 1 wei 存款"稀释**
- 攻击者"首次 1 wei"攻击:如果首次按 share/asset 比例,攻击者用 1 wei 拿到 1 share,然后用 100 ETH 存款但只拿到 ~1 share(因为 totalSupply 涨得比 totalAssets 多),后续 LP 亏
- 实际:首次 1:1 之后,totalSupply = totalAssets,后续 deposits 按 1:1 走

| 版本 | 文件 | 代码量 |

| **raw** | `src/raw/ERC4626.sol` + `IERC4626.sol` | ~179 + (~30) 行 |

## 4. 合约设计

### 4.1 状态

```solidity
ERC20 private immutable _asset;       // 底层资产(如 USDC)
uint8 private immutable _decimals;    // 沿用 asset 的精度
```

share 的总流通量来自继承的 OZ `ERC20._totalSupply`;share 的余额来自 `balanceOf`。

### 4.2 四组核心函数

| 输入/输出 | 资产 → 份额 | 份额 → 资产 |
|---------|----------|----------|
| **指定资产** | `deposit(assets, receiver) → shares` | `withdraw(assets, receiver, owner) → shares` |
| **指定份额** | `mint(shares, receiver) → assets` | `redeem(shares, receiver, owner) → assets` |

教学点:**输入输出对称**。deposit 知道"我付多少 asset",反算 share;mint 知道"我要多少 share",反算 asset。

### 4.3 四个 preview 函数(链下预估用)

```solidity
function previewDeposit(uint256 assets) returns (uint256) { return convertToShares(assets); }
function previewMint(uint256 shares)    returns (uint256) { return convertToAssets(shares); }
function previewWithdraw(uint256 assets) returns (uint256) { return convertToShares(assets); }
function previewRedeem(uint256 shares)   returns (uint256) { return convertToAssets(shares); }
```

`preview*` 系列是"链下预估",不修改状态 —— 前端在用户调 `deposit` 前先 `previewDeposit(1000e18)` 算出"我将得到多少 share"。

### 4.4 四个 max 函数(限额查询)

```solidity
function maxDeposit(address)  public view returns (uint256) { return type(uint256).max; }  // 无限
function maxMint(address)     public view returns (uint256) { return type(uint256).max; }  // 无限
function maxWithdraw(address owner) public view returns (uint256) { return convertToAssets(balanceOf(owner)); }  // 我能提多少
function maxRedeem(address owner)    public view returns (uint256) { return balanceOf(owner); }  // 我能销多少
```

教学点:`maxDeposit = uint256.max` 表示"不限存款"(生产中可能改为"存款上限")。`maxWithdraw/redeem` 是基于"你当前持有多少 share"。

### 4.5 业务流程

```
用户:asset.approve(vault, 1000e18)
     ↓
用户:vault.deposit(1000e18, msg.sender)  ← 付 1000e18 asset,拿 1000e18 share
     ↓
金库:
  shares = previewDeposit(assets)  ← 1000e18 (1:1 首次)
  asset.transferFrom(user, vault, assets)  ← 1000e18 asset 入金库
  share._mint(receiver, shares)  ← 1000e18 share 铸给用户
  emit Deposit(...)
       ↓
时间推移,金库收益(实际生产中:DeFi 收益进来,totalAssets 增长)
  totalAssets 涨了,totalSupply 不变 → share 价值升高
       ↓
用户:vault.redeem(500e18, msg.sender, msg.sender)  ← 销 500e18 share,提走对应 asset
     ↓
金库:
  assets = previewRedeem(shares)
  share._burn(owner, shares)
  asset.transfer(receiver, assets)
  emit Withdraw(...)
```

## 5. 代码拆解

### 5.1 raw 实现 —— `src/raw/ERC4626.sol`

#### deposit(assets, receiver) → shares
```solidity
function deposit(uint256 assets, address receiver) public virtual returns (uint256 shares) {
    shares = previewDeposit(assets);  // 链下预览

    // 先 transferFrom 后 mint(CEI 变体,防重入)
    _asset.transferFrom(msg.sender, address(this), assets);
    _mint(receiver, shares);

    emit Deposit(msg.sender, receiver, assets, shares);
}
```

要点:
- `previewDeposit` 提前算好 share(实际上链上 vs 链下结果应一致 —— 这是 ERC4626 的 invariant)
- 顺序:先收 asset 后铸 share(如果先铸后收,用户可拿到 share 但没付 asset)

#### withdraw(assets, receiver, owner) → shares
```solidity
function withdraw(uint256 assets, address receiver, address owner) public virtual returns (uint256 shares) {
    shares = previewWithdraw(assets);
    
    if (msg.sender != owner) {
        _spendAllowance(owner, msg.sender, shares);  // 第三方调用需 allowance
    }
    
    _burn(owner, shares);                          // 销 share
    _asset.transfer(receiver, assets);             // 转 asset
    
    emit Withdraw(msg.sender, receiver, owner, assets, shares);
}
```

要点:
- 三个地址:`msg.sender`(调用方)、`receiver`(收款方)、`owner`(share 持有方),可分离
- `if (msg.sender != owner) { spendAllowance }` 允许第三方帮 owner 提款(需 owner 事先 approve)

#### convertToShares / convertToAssets:核心会计
```solidity
function convertToShares(uint256 assets) public view returns (uint256) {
    uint256 supply = totalSupply();
    return supply == 0 ? assets : assets * supply / totalAssets();
}

function convertToAssets(uint256 shares) public view returns (uint256) {
    uint256 supply = totalSupply();
    return supply == 0 ? shares : shares * totalAssets() / supply;
}
```

教学点:
- **`supply == 0` 时 1:1** 是核心防御:首次存款防"1 wei 攻击"
- 后续:`assets * supply / totalAssets` 是"按总资产占比算份额"
  - 例子:totalAssets = 100,totalSupply = 200(share 价值 0.5 asset),存入 50 asset → 50*200/100 = 100 share(share 价值仍 0.5 asset,平衡)
- 注意:**先乘后除**避免精度损失;但要先检查 `assets * supply` 不会溢出(uint256 上限)

### 步骤 5:重点测试 —— 首次 1:1 + 后续按比例(`test/raw/ERC4626.t.sol`)

```solidity
function testDeposit() public {
    uint256 assets = 1000e18;
    uint256 shares = vault.deposit(assets, address(this));

    assertEq(shares, assets);                                  // 首次 1:1
    assertEq(vault.balanceOf(address(this)), assets);          // 持有 1000e18 share
    assertEq(vault.totalAssets(), assets);                     // 金库有 1000e18 asset
    assertEq(asset.balanceOf(address(this)), 10000e18 - assets);  // 自己的 asset 减 1000e18
}

function testProportionalDeposit() public {
    vault.deposit(1000e18, address(this));  // 第一个 LP
    assertEq(vault.balanceOf(address(this)), 1000e18);
    assertEq(vault.totalAssets(), 1000e18);

    asset.mint(address(0xAbcd), 1000e18);
    vm.prank(address(0xAbcd));
    asset.approve(address(vault), type(uint256).max);
    vm.prank(address(0xAbcd));
    uint256 shares = vault.deposit(1000e18, address(0xAbcd));  // 第二个 LP

    assertEq(shares, 1000e18);  // 1:1 (因为 totalAssets == totalSupply,等比例)
}
```

教学点:
- **首次 1:1**:`supply == 0` 时 convertToShares(assets) = assets
- **后续按比例**:因为 totalAssets == totalSupply,公式 `assets * supply / totalAssets = assets` 仍得到 1:1
- 第二次"按比例"的效果要在"share 价值变化"(如收益进来,totalAssets > totalSupply)后才明显

## 8. 常见错误排查

### 错误 1:`deposit` 时 `transferFrom` fail(allowance 不足)

- **常见原因**:用户没先 `asset.approve(vault, amount)`
- **解决步骤**:`asset.approve(vault, type(uint256).max)` 一次性无限授权
- **验证方式**:`setUp` 中 `asset.approve(address(vault), type(uint256).max)` 是前置

### 错误 2:`withdraw` 时 `spendAllowance` revert

- **常见原因**:第三方(msg.sender != owner)想提款,owner 没给 share 的 allowance
- **解决步骤**:
  - 走 owner 自己的:`withdraw(amount, msg.sender, msg.sender)`,无需 allowance
  - 第三方代提:`share.approve(spender, shares)`,然后 `spender.withdraw(amount, spender, owner)`
- **验证方式**:`testWithdraw` 中 `withdraw(500e18, address(this), address(this))` 三个地址都是 this

### 错误 3:`convertToShares` 算出的 share 太小(精度损失)

- **常见原因**:`assets * supply / totalAssets` 整数除法丢精度
- **解决步骤**:
  - 用 OZ 完整版(OZ 内部用 mulDiv 库精确除法)
  - 大额用 wei 精度
- **验证方式**:举例:assets=1,supply=1e18,totalAssets=1e18+1 → 1*1e18/(1e18+1) = 0(整数除法),精度损失 1 wei

### 错误 4:首次存款后,后续存款全部"被稀释"

- **常见原因**:有人抢先存 1 wei,导致 totalSupply = 1,你存 1000 ETH 只能拿到 0 share
- **解决步骤**:用 raw 那种"首次 1:1"逻辑(本项目已用)
- **验证方式**:`testDeposit` 首次 1:1,`testProportionalDeposit` 第二次也 1:1(因为 totalAssets == totalSupply)

## 9. 本节总结

- ERC4626 = **代币化金库标准**,统一 DeFi 金库接口
- 核心 4 函数:`deposit / mint / withdraw / redeem`,输入输出对称
- 4 个 preview 函数链下预估,4 个 max 函数限额查询
- **首次 1:1 存款** 防"1 wei 攻击"
- **share 是 ERC20**:可转账、可组合、可借贷抵押
- 实战:Aave aUSDC、Compound cETH、Lido stETH、Yearn Vault
- 与本单元其他课对比:本课是"标准"课,不是业务
