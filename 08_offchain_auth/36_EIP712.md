## 3. 先讲结论

**EIP-712 是"结构化数据签名"标准 —— 让钱包(MetaMask)显示可读的字段名(像表格),而不是 hex 串**。典型场景:
- **ERC20 Permit**(EIP-2612,下一课):用户签"授权 X 卖我 Y token",钱包显示 `Spender / Value / Nonce / Deadline`
- **Uniswap Permit2**:链下授权任意 token
- **OpenSea Seaport**:出价签名,字段清晰可见
- **Dai 投票**:对链下提案签名

**与 eth_sign(35 课)的核心差异**:

| 维度 | eth_sign (35 课) | EIP-712 (本课) |
|------|------------------|----------------|
| 钱包显示 | `0xabc123...` 不可读 | 表格形式(`Owner / Spender / Value`) |
| 签名前缀 | `"\x19Ethereum Signed Message:\n32"` | `"\x19\x01"` |
| 域绑定 | 仅 `msg.sender == signer` | `chainId + verifyingContract + name/version` |
| 防跨链重放 | ❌ | ✅ |
| 防跨合约重放 | ❌ | ✅ |
| 字段约束 | 仅靠程序逻辑 | 标准 `typeHash` 校验字段名+类型 |

**EIP-712 三段 hash 公式**(本课灵魂):

```
typeHash       = keccak256("EIP712Domain(string name,string version,uint256 chainId,address verifyingContract)")
DOMAIN_SEPARATOR = keccak256(typeHash, name, version, chainId, this)

typeHash       = keccak256("Storage(address spender,uint256 number)")
structHash     = keccak256(typeHash, spender, number)

digest         = keccak256("\x19\x01" ++ DOMAIN_SEPARATOR ++ structHash)
```

`"\x19\x01"` 是 EIP-712 标志(版本 1),与 eth_sign 的 `"\x19Ethereum Signed Message:\n32"` 区分。

本项目同时给出两套实现:

| 版本 | 文件 | 代码量 |
|------|------|--------|
| **raw** | `src/raw/EIP712Storage.sol` + `ECDSA.sol` | ~54 + 31 行 |
| **oz** | `src/oz/EIP712Storage.sol` | ~10 行(继承 raw) |

> 注:本项目 oz 版直接继承 raw 加 OZ 后缀(因 OZ EIP712 抽象合约与 raw 略有不同,本项目选择继承)。**生产环境用 OZ `EIP712.sol` + `ECDSA.sol`**,两者组合后 OZ 帮你处理了域分隔、recover 的安全检查。

## 4. 合约设计

### 4.1 状态

```solidity
bytes32 private constant EIP712DOMAIN_TYPEHASH = keccak256("EIP712Domain(string name,string version,uint256 chainId,address verifyingContract)");
bytes32 private constant STORAGE_TYPEHASH     = keccak256("Storage(address spender,uint256 number)");
bytes32 public DOMAIN_SEPARATOR;            // 部署时计算并固化
uint256 public number;                      // 业务状态
address public owner;                       // 签名者地址
```

两个 `typeHash` 都是 `constant` 字符串 keccak256,**编译期就计算好**,不占 storage 槽。

### 4.2 permitStore 流程

```
链下(owner 用 owner 私钥):
  1. domainSeparator = 合约 DOMAIN_SEPARATOR
  2. structHash = keccak256(abi.encode(STORAGE_TYPEHASH, spender, num))
  3. digest = keccak256("\x19\x01" ++ domainSeparator ++ structHash)
  4. (v, r, s) = sign(ownerPrivateKey, digest)
  5. 把 (num, v, r, s) 发给 spender
       ↓
链上(spender 调):
  6. 重新计算 digest(链上)
  7. recover(digest, v, r, s) → signer
  8. require(signer == owner)
  9. number = num
```

教学点:**`spender` 不是签名的字段,而是 `msg.sender`**。这是为了"用户授权给 spender"的语义,spender 必须是那个真正调用合约的人。

### 4.3 permit 模式

```
传统两步流程:                  EIP-712 permit 一步流程:
1. user.approve(spender)       1. user 签 (spender, value, deadline) 链下
2. spender.transferFrom(user)  2. spender 调 permit + transferFrom 一笔
   (需要 user 先发起一笔交易)      (user 不需要发起任何链上交易,纯链下)
```

permit 模式让"不持有 ETH 的用户也能授权卖币",用户体验大幅提升。

## 5. 代码拆解

### 5.1 raw 实现 —— `src/raw/EIP712Storage.sol`

#### DOMAIN_SEPARATOR:在 constructor 锁定
```solidity
constructor(address _owner) {
    DOMAIN_SEPARATOR = keccak256(abi.encode(
        EIP712DOMAIN_TYPEHASH,
        keccak256(bytes("EIP712Storage")),
        keccak256(bytes("1")),
        block.chainid,
        address(this)        ← verifyingContract
    ));
    owner = _owner;
}
```

要点:
- `keccak256(bytes("..."))` 把字符串 hash 成 32 字节(EIP712Domain 字段要求 bytes32)
- `block.chainid` 防跨链重放(EIP-155)
- `address(this)` 防跨合约重放(不同合约的 DOMAIN_SEPARATOR 不同)
- `name` + `version` 是给人看的标识,钱包会显示"哪个 dapp 的哪个版本"
- **关键**:`DOMAIN_SEPARATOR` 在 constructor 算好后存 storage,后续所有签名都依赖这个固定值

#### permitStore:三段 hash + 验证
```solidity
function permitStore(uint256 _num, bytes memory _signature) public {
    require(_signature.length == 65, "invalid signature length");
    bytes32 r; bytes32 s; uint8 v;
    assembly { ... }

    bytes32 digest = keccak256(abi.encodePacked(
        "\x19\x01",
        DOMAIN_SEPARATOR,
        keccak256(abi.encode(STORAGE_TYPEHASH, msg.sender, _num))
    ));

    address signer = digest.recover(v, r, s);  // using ECDSA for bytes32
    require(signer == owner, "EIP712Storage: Invalid signature");

    number = _num;
}
```

要点:
- `keccak256(abi.encode(STORAGE_TYPEHASH, msg.sender, _num))` = `structHash`
  - 用 `abi.encode` 不用 `packed` —— EIP-712 规范要求每个字段占 32 字节
  - `STORAGE_TYPEHASH` 在前,字段值按 typeHash 中声明顺序
- 链上重新算 digest 与链下必须完全一致
- `using ECDSA for bytes32;` 让 `digest.recover(v, r, s)` 这种语法可用

### 5.2 ECDSA 库的扩展版 (`src/raw/ECDSA.sol`)

相比 35 课,本项目多了一个函数:

```solidity
function recover(bytes32 digest, uint8 v, bytes32 r, bytes32 s) internal pure returns (address) {
    return ecrecover(digest, v, r, s);
}
```

要点:
- 直接接 `(digest, v, r, s)` 四个参数(签名已被解析过)
- `using ECDSA for bytes32;` 让 `bytes32` 类型可以 `.recover(v, r, s)`
- 比 35 课的 `recoverSigner(bytes32, bytes)` 更灵活(不必每次都拼 65 字节)

### 步骤 5:重点测试 —— permit 流程(`test/raw/EIP712Storage.t.sol`)

```solidity
function testPermitStoreWithValidSignature() public {
    uint256 newNum = 100;
    bytes32 domainSeparator = storageContract.DOMAIN_SEPARATOR();
    bytes32 typeHash = keccak256("Storage(address spender,uint256 number)");

    bytes32 digest = keccak256(abi.encodePacked(
        "\x19\x01",
        domainSeparator,
        keccak256(abi.encode(typeHash, address(this), newNum))   // spender = msg.sender
    ));

    (uint8 v, bytes32 r, bytes32 s) = vm.sign(ownerPrivateKey, digest);
    bytes memory signature = abi.encodePacked(r, s, bytes1(v));

    vm.prank(address(this));   // 让 permitStore 内部 msg.sender = address(this)
    storageContract.permitStore(newNum, signature);
    assertEq(storageContract.retrieve(), newNum);
}
```

教学点:
- `vm.addr(ownerPrivateKey)` 从私钥算出 owner 地址(Foundry cheatcode)
- `vm.sign(ownerPrivateKey, digest)` 用 owner 私钥对 digest 签名,模拟"链下签名"
- `vm.prank(address(this))` 让 `permitStore` 内部 `msg.sender = address(this)`,与签名的 `spender` 字段一致
- digest 计算的每一段必须与合约内部 `permitStore` 完全一致,否则 ecrecover 出的 signer ≠ owner

## 8. 常见错误排查

### 错误 1:`permitStore` 报 "EIP712Storage: Invalid signature"

- **常见原因**:
  1. 链上链下 digest 计算的 typeHash / 字段顺序 / encoding 方式不匹配
  2. 链上 `msg.sender` ≠ 签名里的 `spender`
  3. 用了不同的 chainId(跨链重放被防住了)
  4. 签名用的私钥 ≠ owner 私钥
- **解决步骤**:硬编码所有中间值(typeHash, structHash, digest),逐字节对比
- **验证方式**:`testPermitStoreWithValidSignature` 把每段 hash 都显式构造

### 错误 2:钱包(测试用 vm.sign)签出的地址 ≠ owner 地址

- **常见原因**:`vm.sign(privateKey, digest)` 必须用 `ownerAddr = vm.addr(privateKey)` 对应的私钥
- **解决步骤**:setUp 中 `ownerAddr = vm.addr(ownerPrivateKey)`,测试用 `vm.sign(ownerPrivateKey, ...)`
- **验证方式**:在 console.log 打印 `vm.addr(ownerPrivateKey)` 对比 `ownerAddr`

### 错误 3:OZ 版用 OZ EIP712 库时报 "missing _domainSeparatorV4()"

- **常见原因**:继承 OZ `EIP712` 必须 `EIP712("name", "version")` 初始化
- **解决步骤**:`contract Foo is EIP712 { constructor() EIP712("Foo", "1") {} }`
- **验证方式**:本项目 oz 版没引 OZ EIP712 库,改用 raw + OZ 后缀

### 错误 4:`abi.encode` vs `abi.encodePacked` 混用导致 hash 错

- **常见原因**:
  - **structHash** 必须 `abi.encode`(每个字段 32 字节,带 padding)
  - **digest 拼接**用 `abi.encodePacked`(`"\x19\x01" ++ a ++ b`,纯字节拼接)
- **解决步骤**:
  - `structHash`:`keccak256(abi.encode(typeHash, field1, field2, ...))` ← `abi.encode`
  - `digest`:`keccak256(abi.encodePacked("\x19\x01", domainSeparator, structHash))` ← `encodePacked`
- **验证方式**:对照 EIP-712 规范附录,逐字段检查 encoding 方式

## 9. 本节总结

- EIP-712 = **结构化签名**标准,钱包显示可读字段(Owner/Spender/Value),不是 hex
- 三段 hash:`typeHash` → `DOMAIN_SEPARATOR` / `structHash` → `digest`
- `DOMAIN_SEPARATOR = keccak256(typeHash, name, version, chainId, this)` 绑定 4 件事
- `"\x19\x01"` 是 EIP-712 标志,区别于 eth_sign 的 `"\x19Ethereum Signed Message:\n32"`
- `structHash` 用 `abi.encode`(32 字节 padding),`digest` 用 `abi.encodePacked`(纯拼接)
- 防跨链 / 跨合约 / 跨 dapp 重放
- permit 模式 = 用户链下签,合约链上一次完成"授权 + 执行"
- 生产用 OZ `EIP712` 抽象合约,自带 `_domainSeparatorV4()` 等安全实现
- EIP-712 是后续 ERC20Permit(下一课)的标准前置
