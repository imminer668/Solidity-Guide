## 3. 先讲结论

**ERC1155 是"多代币标准",一个合约里可以同时存多种 token** —— 在游戏里,1 号是金币、2 号是宝石、3 号是史诗武器,全在同一个合约里。

| 维度 | ERC20 | ERC721 | ERC1155 |
|------|-------|--------|---------|
| 一份合约管理 | 1 种 token | 1 种 NFT 系列(多 tokenId) | 多种 token(混合同质/非同质) |
| balanceOf | `balanceOf[addr]` | `balanceOf[addr]` (NFT 数量) | `balanceOf(addr, id)` 二维 |
| 批量操作 | ❌ | ❌ | ✅ `safeBatchTransferFrom` |
| 授权 | `approve` + `transferFrom` | `approve` + `setApprovalForAll` | 只有 `setApprovalForAll` |
| 经典应用 | USDT、UNI | BAYC | 游戏道具、Opensea Lazy Mint |

**结论**:同一个合约要管多种 token,选 ERC1155;省 gas、省部署、省接口。

| 版本 | 文件 | 代码量 |
|------|------|--------|
| **raw** | `src/raw/ERC1155.sol` + 5 个接口 | ~245 行 |
| **oz** | `src/oz/MultiToken.sol` | ~25 行 |

## 4. 合约设计

### 4.1 IERC1155 接口规格 (`src/raw/IERC1155.sol`)

```solidity
interface IERC1155 is IERC165 {
    event TransferSingle(address indexed operator, address indexed from, address indexed to, uint256 id, uint256 value);
    event TransferBatch(address indexed operator, address indexed from, address indexed to, uint256[] ids, uint256[] values);
    event ApprovalForAll(address indexed account, address indexed operator, bool approved);
    event URI(string value, uint256 indexed id);

    function balanceOf(address account, uint256 id) external view returns (uint256);
    function balanceOfBatch(address[] calldata accounts, uint256[] calldata ids) external view returns (uint256[] memory);
    function setApprovalForAll(address operator, bool approved) external;
    function isApprovedForAll(address account, address operator) external view returns (bool);
    function safeTransferFrom(address from, address to, uint256 id, uint256 amount, bytes calldata data) external;
    function safeBatchTransferFrom(address from, address to, uint256[] calldata ids, uint256[] calldata amounts, bytes calldata data) external;
}
```

注意三点:
- **没有 `approve(spender, tokenId)`**,只有 `setApprovalForAll`
- **没有 `transferFrom`**,只有 `safeTransferFrom`(必须带接收方校验)
- **多了 `safeBatchTransferFrom`** —— ERC1155 的灵魂特性

### 4.2 raw 实现的 6 个接口文件

| 文件 | 作用 |
|------|------|
| `IERC165.sol` | `supportsInterface` 检查 |
| `IERC1155.sol` | 核心多代币接口 |
| `IERC1155Receiver.sol` | 接收方钩子(`onERC1155Received` / `onERC1155BatchReceived`) |
| `IERC1155MetadataURI.sol` | `uri(id)` 元数据扩展 |
| `String.sol` | uint→string 工具 |
| `ERC1155.sol` | 集大成实现 |

### 4.3 核心状态变量

```solidity
mapping(uint256 => mapping(address => uint256)) private _balances;   // id -> owner -> amount
mapping(address => mapping(address => bool)) private _operatorApprovals; // owner -> operator -> 全量授权
```

**关键设计**:`_balances` 的第一维是 `id`,第二维是 `owner`,顺序与 `balanceOf(account, id)` 的参数顺序相反 —— 是为了同一个 tokenId 的所有持有者数据在存储槽上连续(节省 SLOAD)。

## 5. 代码拆解

### 5.1 raw 实现 —— 看清二维余额怎么动 (`src/raw/ERC1155.sol`)

#### balanceOf:二维查询
```solidity
function balanceOf(address account, uint256 id) public view virtual override returns (uint256) {
    require(account != address(0), "ERC1155: address zero is not a valid owner");
    return _balances[id][account];
}

function balanceOfBatch(address[] memory accounts, uint256[] memory ids)
    public view virtual override returns (uint256[] memory)
{
    require(accounts.length == ids.length, "ERC1155: accounts and ids length mismatch");
    uint256[] memory batchBalances = new uint256[](accounts.length);
    for (uint256 i = 0; i < accounts.length; ++i) {
        batchBalances[i] = balanceOf(accounts[i], ids[i]);
    }
    return batchBalances;
}
```
要点:`balanceOfBatch` 走一次外部调用就拿到 N 个余额,比 N 次 `balanceOf` 省 gas(每次 RPC 都有开销)。

#### safeTransferFrom:单转
```solidity
function safeTransferFrom(address from, address to, uint256 id, uint256 amount, bytes memory data)
    public virtual override
{
    address operator = msg.sender;
    require(
        from == operator || isApprovedForAll(from, operator),
        "ERC1155: caller is not token owner nor approved"
    );
    require(to != address(0), "ERC1155: transfer to the zero address");
    uint256 fromBalance = _balances[id][from];
    require(fromBalance >= amount, "ERC1155: insufficient balance for transfer");
    unchecked { _balances[id][from] = fromBalance - amount; }
    _balances[id][to] += amount;
    emit TransferSingle(operator, from, to, id, amount);
    _doSafeTransferAcceptanceCheck(operator, from, to, id, amount, data);
}
```
要点:
- 权限判断只有 "owner 自己 / 全量授权 operator"(没有 ERC721 那种单 token 授权)
- 余额扣减用 `unchecked`(前面已 require >= amount,不会溢出),省 gas
- 必须在 emit 后做接收方校验

#### safeBatchTransferFrom:批转(ERC1155 的灵魂)
```solidity
function safeBatchTransferFrom(
    address from, address to,
    uint256[] memory ids, uint256[] memory amounts,
    bytes memory data
) public virtual override {
    address operator = msg.sender;
    require(from == operator || isApprovedForAll(from, operator), "...");
    require(ids.length == amounts.length, "...");
    require(to != address(0), "...");
    for (uint256 i = 0; i < ids.length; ++i) {
        uint256 id = ids[i];
        uint256 amount = amounts[i];
        uint256 fromBalance = _balances[id][from];
        require(fromBalance >= amount, "...");
        unchecked { _balances[id][from] = fromBalance - amount; }
        _balances[id][to] += amount;
    }
    emit TransferBatch(operator, from, to, ids, amounts);
    _doSafeBatchTransferAcceptanceCheck(operator, from, to, ids, amounts, data);
}
```
要点:
- 批量转账只发一个 `TransferBatch` 事件 —— 比 N 次 single 转省事件 gas
- 接收方校验也走批量版 `onERC1155BatchReceived`

#### _doSafeTransferAcceptanceCheck:接收方校验
```solidity
function _doSafeTransferAcceptanceCheck(
    address operator, address from, address to,
    uint256 id, uint256 amount, bytes memory data
) private {
    if (to.code.length > 0) {
        try IERC1155Receiver(to).onERC1155Received(operator, from, id, amount, data)
            returns (bytes4 response)
        {
            if (response != IERC1155Receiver.onERC1155Received.selector) {
                revert ERC1155InvalidReceiver(to);
            }
        } catch (bytes memory reason) {
            if (reason.length == 0) revert ERC1155InvalidReceiver(to);
            else { assembly { revert(add(32, reason), mload(reason)) } }
        }
    }
}
```
和 ERC721 的 `_checkOnERC721Received` 一个套路,只是 selector 不同。

### 5.2 oz 实现 —— 几行就够 (`src/oz/MultiToken.sol`)

```solidity
import {ERC1155} from "@openzeppelin/contracts/token/ERC1155/ERC1155.sol";

contract MultiToken is ERC1155 {
    uint256 public constant MAX_ID = 10000;

    constructor(string memory uri_) ERC1155(uri_) {}

    function mint(address to, uint256 id, uint256 amount) external {
        require(id < MAX_ID, "id overflow");
        _mint(to, id, amount, "");
    }

    function mintBatch(address to, uint256[] memory ids, uint256[] memory amounts) external {
        for (uint256 i = 0; i < ids.length; i++) {
            require(ids[i] < MAX_ID, "id overflow");
        }
        _mintBatch(to, ids, amounts, "");
    }
}
```
要点:
- OZ 构造函数传入 `uri_`(单一 baseURI,所有 tokenId 共享)
- 业务壳只加了 `MAX_ID` 上限校验和 mint 包装
- 所有 transfer / approve / receiver-check 全在 OZ 基类里

### 5.3 对照看 —— raw vs oz

| 维度 | raw | oz |
|------|-----|----|
| 文件数 | 6 个(1 实现 + 5 接口) | 1 个(继承基类) |
| `_doSafeTransferAcceptanceCheck` | 自己写 try-catch | OZ 内置 |
| URI 模板 | 自己拼 `_baseURI() + id.toString()` | 构造时一次性传入 |
| 安全性 | 依赖 0.8+ + 自写 require | OZ 审计版 |
| 适用 | 学原理 | 上线主网 |

```solidity
function testMintBatch() public {
    uint256[] memory ids = new uint256[](2);
    ids[0] = 1; ids[1] = 2;
    uint256[] memory amounts = new uint256[](2);
    amounts[0] = 100; amounts[1] = 200;
    token.mintBatch(address(2), ids, amounts);
    assertEq(token.balanceOf(address(2), 1), 100);
    assertEq(token.balanceOf(address(2), 2), 200);
}

function testBalanceOfBatch() public {
    token.mint(address(2), 1, 100);
    token.mint(address(2), 2, 200);
    address[] memory accounts = new address[](2);
    accounts[0] = address(2); accounts[1] = address(2);
    uint256[] memory ids = new uint256[](2);
    ids[0] = 1; ids[1] = 2;
    uint256[] memory balances = token.balanceOfBatch(accounts, ids);
    assertEq(balances[0], 100);
    assertEq(balances[1], 200);
}
```
教学点:`balanceOfBatch` 的 `accounts` 和 `ids` 是"按位置一一对应"的两个数组,不是笛卡尔积。要查 N 个 (account, id) 组合,这两个数组都得是 N 个元素。

## 8. 常见错误排查

### 错误 1:`safeTransferFrom` 给合约地址永远 revert

- **常见原因**:目标合约没实现 `IERC1155Receiver`
- **解决步骤**:接收合约里实现两个回调:
  ```solidity
  function onERC1155Received(address, address, uint256, uint256, bytes calldata)
      external pure returns (bytes4)
  { return IERC1155Receiver.onERC1155Received.selector; }

  function onERC1155BatchReceived(address, address, uint256[] calldata, uint256[] calldata, bytes calldata)
      external pure returns (bytes4)
  { return IERC1155Receiver.onERC1155BatchReceived.selector; }
  ```
- **验证方式**:写 Mock 接收合约,分别测试单转和批转

### 错误 2:`balanceOfBatch` 报数组长度不匹配

- **常见原因**:`accounts` 和 `ids` 长度不一致
- **解决步骤**:确保两个数组都是相同长度(N)
- **验证方式**:`testBalanceOfBatch` 中 `accounts` 和 `ids` 都是 2 个元素

### 错误 3:想给 spender 授权某一个 tokenId,但找不到 approve 方法

- **常见原因**:ERC1155 标准就不支持单 token 授权
- **解决步骤**:只能 `setApprovalForAll(operator, true)`,授权后 operator 能动 owner 名下所有 tokenId
- **验证方式**:看 IERC1155 接口确认 —— 全程没有 `approve(spender, id)` 方法

### 错误 4:OZ 版的 `uri(id)` 始终返回同一个字符串,不带 id

- **常见原因**:OZ 的 `ERC1155` 默认 `uri()` 返回构造时传入的 `uri_` 原样,不替换 `{id}`
- **解决步骤**:OZ 约定 URI 模板中用 `{id}` 占位符,**前端**负责把 `{id}` 替换成具体 id 的 hex(64 位 0 填充)
- **验证方式**:链上的 `uri(1)` 和 `uri(2)` 返回相同字符串,前端拿到后自己替换

## 9. 本节总结

- ERC1155 的核心是 **`(id, account) -> amount`** 的二维余额
- 一个合约管多种 token —— 部署一次,无限扩展
- 批量操作(`safeBatchTransferFrom` / `mintBatch` / `balanceOfBatch`)是 ERC1155 的灵魂,显著省 gas
- 授权只能"全量授权",没有单 token 授权
- raw 拆 6 个接口文件,看清 EIP-1155 模块化;oz 一行 import 全继承
- URI 用 `{id}` 占位符,前端替换 —— 不在链上做字符串拼接
