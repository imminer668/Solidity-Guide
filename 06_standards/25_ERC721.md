- 理解 `safeTransferFrom` 为什么要校验 `IERC721Receiver`

## 2. 前置知识

## 3. 先讲结论

**ERC721 是 NFT 的事实标准** —— BAYC、CryptoPunks、ENS 域名、Uniswap V3 LP 头寸全是 ERC721。它最大的特点:

| 维度 | ERC20 | ERC721 |
|------|-------|--------|
| 单位 | 数量(`amount`) | 编号(`tokenId`) |
| 所有权 | `balanceOf[addr]` 是数字 | 每个 `tokenId` 唯一映射到一个地址 |
| 同质性 | 可拆分、可合并 | 每个 token 独一无二 |
| 转账 | 转金额 | 转编号 |

本项目同时给出两套实现:

| 版本 | 文件 | 代码量 |
|------|------|--------|
| **raw** | `src/raw/ERC721.sol` + 5 个接口 | ~180 行 |
| **oz** | `src/oz/NFTToken.sol` | ~30 行 |

## 4. 合约设计

### 4.1 IERC721 接口规格 (`src/raw/IERC721.sol`)

```solidity
interface IERC721 is IERC165 {
    event Transfer(address indexed from, address indexed to, uint256 indexed tokenId);
    event Approval(address indexed owner, address indexed approved, uint256 indexed tokenId);
    event ApprovalForAll(address indexed owner, address indexed operator, bool approved);

    function balanceOf(address owner) external view returns (uint256);
    function ownerOf(uint256 tokenId) external view returns (address);
    function safeTransferFrom(address from, address to, uint256 tokenId, bytes calldata data) external;
    function safeTransferFrom(address from, address to, uint256 tokenId) external;
    function transferFrom(address from, address to, uint256 tokenId) external;
    function approve(address to, uint256 tokenId) external;
    function setApprovalForAll(address operator, bool approved) external;
    function getApproved(uint256 tokenId) external view returns (address);
    function isApprovedForAll(address owner, address operator) external view returns (bool);
}
```

### 4.2 raw 实现的 5 个接口文件

| 文件 | 作用 |
|------|------|
| `IERC165.sol` | `supportsInterface` 检查 —— 让链上其他合约能问"你支持 ERC721 吗" |
| `IERC721.sol` | 核心 NFT 接口 |
| `IERC721Receiver.sol` | 接收方钩子,`safeTransferFrom` 转给合约时必须实现 |
| `IERC721Metadata.sol` | `name` / `symbol` / `tokenURI` 元数据扩展 |
| `String.sol` | uint→string 工具,用来拼 `tokenURI` |

oz 实现一行 `import {ERC721} from "@openzeppelin/contracts/token/ERC721/ERC721.sol"` 就把这些全继承下来了。

### 4.3 核心状态变量(raw 版本)

```solidity
mapping(uint256 => address) private _owners;                        // tokenId -> 持有者
mapping(address => uint256) private _balances;                      // 持有者 -> 数量
mapping(uint256 => address) private _tokenApprovals;                // tokenId -> 单 token 授权地址
mapping(address => mapping(address => bool)) private _operatorApprovals; // owner -> operator -> 全量授权开关
```

### 4.4 两种授权粒度

| 方法 | 作用域 | 适用场景 |
|------|-------|---------|
| `approve(spender, tokenId)` | 单个 tokenId | 挂单某只 NFT 时,授权给市场合约 |
| `setApprovalForAll(operator, true)` | owner 名下全部(含未来 mint 的) | 上架到 OpenSea 等市场时,一次性授权 |

## 5. 代码拆解

### 5.1 raw 实现 —— 看清每个映射 (`src/raw/ERC721.sol`)

#### 核心查询:ownerOf / balanceOf
```solidity
function ownerOf(uint256 tokenId) public view override returns (address owner) {
    owner = _owners[tokenId];
    require(owner != address(0), "token doesn't exist");
}

function balanceOf(address owner) external view override returns (uint256) {
    require(owner != address(0), "owner = zero address");
    return _balances[owner];
}
```
要点:`ownerOf` 不存在的 tokenId 必须 revert,这是 EIP-721 强制要求。

#### 单 token 授权 + 全量授权
```solidity
function approve(address to, uint256 tokenId) external override {
    address owner = _owners[tokenId];
    require(
        msg.sender == owner || _operatorApprovals[owner][msg.sender],
        "not owner nor approved for all"
    );
    _approve(owner, to, tokenId);
}

function setApprovalForAll(address operator, bool approved) external override {
    _operatorApprovals[msg.sender][operator] = approved;
    emit ApprovalForAll(msg.sender, operator, approved);
}
```
要点:`approve` 时检查"是 owner 本人 或 已被全量授权",这两种身份都可以发起单 token 授权。

#### transferFrom 的权限三态
```solidity
function _isApprovedOrOwner(address owner, address spender, uint256 tokenId)
    private view returns (bool)
{
    return (spender == owner ||
        _tokenApprovals[tokenId] == spender ||
        _operatorApprovals[owner][spender]);
}

function transferFrom(address from, address to, uint256 tokenId) external override {
    address owner = ownerOf(tokenId);
    require(_isApprovedOrOwner(owner, msg.sender, tokenId), "not owner nor approved");
    _transfer(owner, from, to, tokenId);
}
```
要点:`spender` 满足"是 owner / 单 token 授权 / 全量授权" 任一即可。

#### _transfer:转账时清掉单 token 授权
```solidity
function _transfer(address owner, address from, address to, uint256 tokenId) private {
    require(from == owner, "not owner");
    require(to != address(0), "transfer to the zero address");

    _approve(owner, address(0), tokenId);  // 转账后清掉之前的授权,防止前所有者再操作

    _balances[from] -= 1;
    _balances[to] += 1;
    _owners[tokenId] = to;

    emit Transfer(from, to, tokenId);
}
```
要点:`_approve(owner, address(0), tokenId)` 这一行是 ERC721 标准要求的"转账后撤销授权"。

#### safeTransferFrom:防止 NFT 被锁死在合约里
```solidity
function _checkOnERC721Received(address from, address to, uint256 tokenId, bytes memory data) private {
    if (to.code.length > 0) {
        try IERC721Receiver(to).onERC721Received(msg.sender, from, tokenId, data) returns (bytes4 retval) {
            if (retval != IERC721Receiver.onERC721Received.selector) {
                revert ERC721InvalidReceiver(to);
            }
        } catch (bytes memory reason) {
            if (reason.length == 0) revert ERC721InvalidReceiver(to);
            else {
                assembly { revert(add(32, reason), mload(reason)) }
            }
        }
    }
}
```
教学要点:
- `to.code.length > 0` 判断目标是合约(普通地址 code length = 0)
- 合约必须实现 `onERC721Received` 并返回 `IERC721Receiver.onERC721Received.selector`
- 防止把 NFT 转到不会处理 NFT 的合约,导致永久锁死

#### tokenURI:元数据指针
```solidity
function tokenURI(uint256 tokenId) public view virtual override returns (string memory) {
    require(_owners[tokenId] != address(0), "Token Not Exist");
    string memory baseURI = _baseURI();
    return bytes(baseURI).length > 0
        ? string(abi.encodePacked(baseURI, tokenId.toString()))
        : "";
}

function _baseURI() internal view virtual returns (string memory) {
    return "";  // 默认空,子合约重写
}
```
要点:NFT 元数据(名字、图片)不存链上,链上只存指针 URL;通常用 IPFS。

### 5.2 oz 实现 —— 几行就够 (`src/oz/NFTToken.sol`)

```solidity
import {ERC721} from "@openzeppelin/contracts/token/ERC721/ERC721.sol";

contract NFTToken is ERC721 {
    uint256 public maxSupply;

    constructor(string memory name_, string memory symbol_, uint256 maxSupply_)
        ERC721(name_, symbol_)
    {
        maxSupply = maxSupply_;
    }

    function mint(address to, uint256 tokenId) external {
        require(tokenId < maxSupply, "tokenId out of range");
        _mint(to, tokenId);
    }

    function _baseURI() internal view override returns (string memory) {
        return "ipfs://QmeSjSinHpPnmXmspMjwiXyN6zS4E9zccariGR3jxcaWtq/";
    }
}
```
要点:
- 继承 OZ 的 `ERC721`,把 `transferFrom` / `safeTransferFrom` / `approve` 等全继承下来
- 自己只需要写"业务壳" —— 限量 `maxSupply` + 重写 `_baseURI`
- OZ 已实现 `_checkOnERC721Received`,无需重写

### 5.3 对照看 —— raw vs oz

| 维度 | raw | oz |
|------|-----|----|
| 文件数 | 6 个(1 实现 + 5 接口) | 1 个(继承基类) |

| 安全性 | 依赖 0.8+ 溢出检查 + 自己写的 require | OZ 审计版,边界已处理 |

## 8. 常见错误排查

### 错误 1:`safeTransferFrom` 给合约地址永远 revert

- **常见原因**:目标合约没实现 `IERC721Receiver` 接口
- **解决步骤**:在接收合约里:
  ```solidity
  function onERC721Received(address, address, uint256, bytes calldata)
      external pure returns (bytes4)
  { return IERC721Receiver.onERC721Received.selector; }
  ```
- **验证方式**:写个 Mock 接收合约测试,体会"普通地址收 NFT 没问题、合约必须先告知能收"

### 错误 2:`approve` 报 "not owner nor approved for all"

- **常见原因**:当前调用者既不是 NFT owner,也没有 `setApprovalForAll` 授权
- **解决步骤**:先 `vm.prank(owner)` 切换调用者,或先全量授权
- **验证方式**:`testApprove` 中 `address(this)` 是 owner,所以可以直接 `approve`

### 错误 3:转账后,前一个被授权地址仍能操作

- **常见原因**:`_transfer` 里漏写 `_approve(owner, address(0), tokenId)`
- **解决步骤**:转账时必须把单 token 授权清零
- **验证方式**:加测试 —— mint → approve → transferFrom → 旧 approved 地址再 approve 应失败

### 错误 4:`tokenURI` 返回空字符串

- **常见原因**:raw 版 `_baseURI()` 默认返回 `""`,而你没重写
- **解决步骤**:在子合约里 override `_baseURI`,或直接重写 `tokenURI`
- **验证方式**:oz 版 `NFTToken` 重写了 `_baseURI` 为 IPFS 路径,`testTokenURI` 断言长度 > 0

## 9. 本节总结

- ERC721 的核心是 **`tokenId -> address`** 的一对一映射
- 两种授权:`approve`(单 NFT) vs `setApprovalForAll`(全量)
- `safeTransferFrom` 比 `transferFrom` 多了 `IERC721Receiver` 校验,防止把 NFT 锁死在合约
- raw 实现拆出 5 个接口文件,看清 EIP-721 的"模块化"设计
- oz 实现一行 import 全继承,生产环境标配
- `tokenURI` 只是个链下指针,真正的元数据在 IPFS / Arweave
